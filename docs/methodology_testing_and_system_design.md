## 2. Что должно быть реализовано по постановке задачи

По методичке система должна обеспечивать:

1. Формирование таблицы классификации вероятностей отказов для 6 профилей атак (`Лин_Н`, `Лин_С`, `Лин_В`, `Exp_Н`, `Exp_С`, `Exp_В`) на интервал е `t = 1..17`.
2. Построение графиков вероятности отказа `pA(t)` для заданных атак при `p(ai)=1.0`.
3. Построение графиков вероятности обнаружения `P(p(t))` для одиночного тестирования.
4. Построение графиков вероятности обнаружения `P(p(t,k))` для коллаборационного тестирования.
5. Исследование влияния факторов:
   - тип атаки (линейная/экспоненциальная),
   - вероятность появления `p(ai)`,
   - режимы `p(t) > 0.5` и `p(t) < 0.5` (в работе: коэффициенты `0.9` и `0.41`),
   - диапазоны параметров `n, k`.
6. Жадный алгоритм минимального покрытия на матрице смежности `15x15` при количестве связей в строке `[1; 6]`.

## 3. Формулы, используемые в системе

### 3.1. Вероятность атаки

- Линейная модель: `pA(t) = a*t + b`
- Экспоненциальная модель: `pA(t) = 1 - a*exp(-b*t)`
- В системе значения ограничиваются диапазоном `[0, 1]` (`clamp`) для устойчивости.

### 3.2. Обнаружение уязвимости

- Одиночное тестирование (геометрическая модель):
  `P_single = p * (1 - p)^(k-1)`
- Коллаборация (биномиальная модель):
  `P_collab = C(n,k) * p^k * (1-p)^(n-k)`

### 3.3. Учёт противодействия

- Вероятность отказа тестирования в текущей реализации:
  `p_fail = p(ai) * pA(t)`
- Вероятность обнаружения с учётом противодействия:
  `P_counter = (1 - p_fail) * P`

### 3.4. Режимы p(t)>0.5 и p(t)<0.5

Для сценариев из методички используются два режима:

- высокий режим: `p_detect(t) = 0.9 * pA(t)`
- низкий режим: `p_detect(t) = 0.41 * pA(t)`

## 4. Пошаговое тестирование для вариантов 2, 5, 9

> Важно: вы указали, что варианты 2, 5, 9 у вас уже посчитаны. Значит значения коэффициентов `a, b` для нужных профилей вы берёте из своего расчёта/таблицы и подставляете в UI.

### 4.1. Подготовка входных данных для каждого варианта

Для каждого из вариантов (2, 5, 9) подготовьте:

1. Три линейных профиля (`Лин_Н`, `Лин_С`, `Лин_В`) с `a,b`.
2. Три экспоненциальных профиля (`Exp_Н`, `Exp_С`, `Exp_В`) с `a,b`.
3. Рабочие параметры эксперимента:
   - `n` (в системе допустимо `1..8`),
   - `k` (в системе допустимо `1..5`, и `k <= n`),
   - `p_ai` (обычно `0.33` для анализа влияния вероятности появления),
   - `p_single`:
     - `0.9` для режима `p(t)>0.5`,
     - `0.41` для режима `p(t)<0.5`.

Рекомендуется сделать для каждого профиля два эксперимента: один с `p_single=0.9`, второй с `p_single=0.41`.

### 4.2. Создание атак в интерфейсе

Для каждого варианта:

1. Откройте главную (`/` → список атак).
2. Создайте 6 атак:
   - тип `linear` и нужные `a,b` (3 записи),
   - тип `exponential` и нужные `a,b` (3 записи).
3. Проверьте, что карточки атак отображаются в списке.

Контроль:

- Для линейных атак при росте `t` значения `pA(t)` должны расти линейно.
- Для экспоненциальных — расти быстрее в начале и затем насыщаться.

### 4.3. Запуск экспериментов

Для каждого профиля атаки:

1. Перейдите в «Эксперименты» → «Запустить эксперимент».
2. Выберите атаку.
3. Укажите `n`, `k`, `p_ai`, `p_single`.
4. Сохраните эксперимент (расчёт запустится автоматически).
5. Повторите:
   - для `p_single = 0.9`,
   - для `p_single = 0.41`.

Минимальный план на один вариант: `6 атак * 2 режима = 12 экспериментов`.

### 4.4. Что проверять в результатах (чек-лист)

#### A. График отказа `pA(t)`

Ожидание:

- линейная атака: почти прямая линия вверх;
- экспоненциальная: нелинейный рост (быстрее в начале).

#### B. График `P(p(t))` (одиночное)

Ожидание:

- кривая для `0.9 * pA(t)` должна быть выше, чем для `0.41 * pA(t)`;
- при фиксированном `k` форма зависит от роста `pA(t)`.

#### C. График `P(p(t,k))` (коллаборация)

Ожидание:

- кривая чувствительна к `n` и `k`;
- при одинаковых `n,k` режим `0.9` выше режима `0.41`.

#### D. График с противодействием

Ожидание:

- `p_single_counter <= p_single` и `p_collab_counter <= p_collab` для каждого `t`.

#### E. Таблица классификации (6 профилей)

Ожидание:

- значения в диапазоне `[0,1]`;
- при росте `t` как правило не убывают (для заданных параметров из методички);
- профили высокой интенсивности должны быть выше низкой/средней.

#### F. Таблица сетки `n=[1..8], k=[1..5]`

Ожидание:

- ячейки с `k>n` пустые/`—`;
- остальные ячейки в `[0,1]`.

#### G. Матрица и покрытие

Ожидание:

- матрица `15x15`;
- в каждой строке число связей в диапазоне `[1,6]`;
- выводится набор строк покрытия (жадный алгоритм).

## 6. Техническое устройство системы (для раздела «реализация»)

## 6.1. Архитектура

Система построена на Ruby on Rails (MVC):

- **Model**: `Attack`, `Experiment`, `ExperimentResult`, `AdjacencyMatrix`
- **Controller**: `AttacksController`, `ExperimentsController`
- **Service**: `ProbabilityService`, `ExperimentRunner`, `MethodologyReportService`, `MatrixGenerator`, `GreedyCover`
- **View**: страницы атак и экспериментов, графики через `line_chart`.

## 6.2. Модели

### Attack

Назначение: хранение параметров атаки и вычисление `pA(t)`.

- Поля: `attack_type`, `a`, `b`
- Методы:
  - `probability_at(t)`
  - `linear_probability(t)`
  - `exponential_probability(t)`
  - `attack_level(t)`

Файл: `app/models/attack.rb`

### Experiment

Назначение: конфигурация конкретного запуска.

- Связь: `belongs_to :attack`
- Параметры запуска: `n`, `k`, `p_ai`, `p_single`
- Валидации:
  - `1 <= n <= 8`
  - `1 <= k <= 5`
  - `k <= n`
  - `0 <= p_ai <= 1`
  - `0 <= p_single <= 1`

Файл: `app/models/experiment.rb`

### ExperimentResult

Назначение: хранение результатов по каждому шагу времени `t`.

Поля: `t`, `p_attack`, `p_single`, `p_collab`, `p_single_counter`, `p_collab_counter`.

Файл: `app/models/experiment_result.rb`

### AdjacencyMatrix

Назначение: хранение матрицы смежности и покрытия в `data` (JSON).

Файл: `app/models/adjacency_matrix.rb`

## 6.3. Сервисы

### ProbabilityService

Реализует базовые формулы вероятности:

- `single_test(p_t, k)`
- `collab_test(p_t, k, n)`
- `with_counteraction(prob, p_fail)`

Файл: `app/services/probability_service.rb`

### ExperimentRunner

Исполняет расчёт эксперимента:

1. Очищает старые результаты эксперимента.
2. Для `t=1..17` считает:
   - `p_attack = attack.probability_at(t)`
   - `detect_prob = p_single * p_attack`
   - `p_single`, `p_collab`
   - `p_fail = p_ai * p_attack`
   - `p_single_counter`, `p_collab_counter`
3. Сохраняет строки `ExperimentResult`.
4. Генерирует матрицу и покрытие.

Файл: `app/services/experiment_runner.rb`

### MethodologyReportService

Формирует отчётные данные под методичку:

- таблица классификации 6 профилей;
- ряды `pA(t)`;
- ряды для режимов `0.9/0.41`;
- агрегированные ряды по `p(ai)=0.33`;
- сетка `P(p(t,k))` по диапазонам `n,k`.

Файл: `app/services/methodology_report_service.rb`

### MatrixGenerator

Генерирует матрицу `15x15`:

- в строке от `1` до `6` единиц;
- пытается обеспечить покрываемость столбцов.

Файл: `app/services/matrix_generator.rb`

### GreedyCover

Жадный алгоритм покрытия:

- выбирает строку, покрывающую максимум непокрытых столбцов;
- повторяет до покрытия/исчерпания.

Файл: `app/services/greedy_cover.rb`

## 6.4. Контроллеры и поток выполнения

### AttacksController

CRUD для профилей атак.

### ExperimentsController

- `create/update` запускают `ExperimentRunner`.
- `show` собирает данные как для обычных графиков эксперимента, так и для отчётных блоков методички через `MethodologyReportService`.

## 7. Практический сценарий «быстрой проверки» (smoke test)

1. Создать 1 линейную и 1 экспоненциальную атаку.
2. Запустить 2 эксперимента для одной атаки:
   - `p_single=0.9`
   - `p_single=0.41`
3. Убедиться, что:
   - графики строятся,
   - линия `0.9` выше `0.41`,
   - есть таблица 6 профилей,
   - есть таблица `n,k`,
   - есть матрица и покрытие.

---

## 8. Ограничения текущей реализации

1. Для блока `p(ai)=0.33` используется усреднение по профилям с весом `0.33`.
2. Таблица классификации использует фиксированные профили из методички (в сервисе), а не пользовательские атаки из БД.
3. Поле `p_single` в эксперименте трактуется как коэффициент режима (`0.9` или `0.41`).
