# Отчет по курсовой работе

## Введение

В рамках курсовой работы рассматривается задача разработки программной системы для исследования методов обнаружения компьютерных вторжений в интеллектуальных сетях. Актуальность задачи определяется необходимостью повышения достоверности контроля состояния сетевых ресурсов и уменьшения вероятности пропуска атак при наличии внешнего противодействия.

В методических указаниях основное внимание уделяется вероятностным моделям обнаружения уязвимостей при одиночном и совместном тестировании, а также оценке влияния параметров атакующих воздействий на вероятность отказа тестирования. Дополнительно ставится задача построения жадного алгоритма покрытия для матрицы смежности размерности `15x15`.

Цель работы состоит в создании программного приложения, позволяющего:

- задавать параметры атак;
- запускать модельные эксперименты;
- строить графики и таблицы по формулам методических указаний;
- анализировать влияние параметров `p(t)`, `p(ai)`, `n`, `k`;
- формировать матрицу смежности и минимальное покрытие.

## 1. Постановка задачи

Согласно методическим указаниям требуется исследовать изменение вероятности обнаружения уязвимостей при коллаборационной стратегии в условиях противодействия тестированию.

В качестве входных данных используются:

- тип атаки: линейная или экспоненциальная;
- параметры атаки `a`, `b`;
- вероятность появления атаки `p(ai)`;
- вероятность однократного обнаружения уязвимости `p(t)`;
- число узлов `n`;
- число тестировщиков `k`.

Требуется:

1. Сформировать таблицу классификации ситуаций обнаружения отказов.
2. Построить графики изменения вероятности отказа `pA(t)` для заданных типов атак.
3. Построить графики вероятности одиночного обнаружения `P(p(t))`.
4. Построить графики вероятности коллаборационного обнаружения `P(p(t,k))`.
5. Провести модельные эксперименты с учетом противодействия тестированию.
6. Реализовать жадный алгоритм покрытия для матрицы смежности `15x15`.

Для студента с порядковым номером `I=1` по правилам методички получаются варианты:

- `N = 2`
- `J = 5`
- `K = 9`

То есть в работе должны быть рассмотрены параметры атак из вариантов `2`, `5`, `9`.

По таблице 2 для варианта `2` используются вероятности:

- `p(t)>0.5 = 0.75`
- `p(t)<0.5 = 0.47`

## 2. Краткие теоретические сведения

### 2.1. Одиночное тестирование

Вероятность обнаружить уязвимость за `k` тестов определяется формулой:

`P(p(t)) = p(t) * (1 - p(t))^(k - 1)`

где:

- `p(t)` — вероятность однократного обнаружения;
- `k` — число повторений теста.

### 2.2. Коллаборационная стратегия

При совместном тестировании используется биномиальная модель:

`P(p(t), k, n) = C(n,k) * p(t)^k * (1-p(t))^(n-k)`

где:

- `n` — число устройств;
- `k` — число тестировщиков.

### 2.3. Модели атак

В методичке рассматриваются два типа атак:

- линейная модель:
  `pA(t) = a*t + b`
- экспоненциальная модель:
  `pA(t) = 1 - a*exp(-b*t)`

Значение `pA(t)` интерпретируется как вероятность противодействия тестированию.

### 2.4. Учет противодействия

В условиях противодействия используются формулы:

`P(pA(t),p(t)) = (1-pA(отк)) * p(t) * (1-p(t))^(k-1)`

`P(pA(t),p(t,k)) = (1-pA(отк)) * C(n,k) * p(t)^k * (1-p(t))^(n-k)`

В реализации для одной активной атаки применяется частный случай:

`pA(отк) = p(ai) * pA(t)`

где:

- `p(ai)` — вероятность появления атаки;
- `pA(t)` — вероятность успешного противодействия для выбранного профиля атаки.

### 2.5. Классификация отказов

В методичке задаются интервалы:

- низкий уровень: `0 <= pA(t) < 0.4`
- средний уровень: `0.4 <= pA(t) < 0.7`
- высокий уровень: `0.7 <= pA(t) <= 1`

Эти интервалы используются при формировании цветовой таблицы классификации.

## 3. Разработка модели исследования, основные соотношения

В приложении реализованы два уровня моделирования:

1. Справочный уровень по методическим указаниям.
2. Уровень конкретного эксперимента.

### 3.1. Справочный уровень

На странице атаки реализованы:

- график выбранной функции `pA(t)`;
- эталонные профили `Лин_Н`, `Лин_С`, `Лин_В`, `Exp_Н`, `Exp_С`, `Exp_В`;
- усредненный график для линейных и экспоненциальных атак при `p(ai)=0.33`;
- отдельный блок по индивидуальным вариантам `2`, `5`, `9` из раздела 3 методички;
- таблица классификации отказов.

Этот уровень нужен для проверки соответствия приложения методичке.

### 3.2. Уровень конкретного эксперимента

На странице эксперимента реализованы:

- график `pA(t)` для выбранной атаки;
- график `p(ai) * pA(t)`;
- график `P(p(t))` без противодействия;
- график `P(p(t,k))` без противодействия;
- график `P(pA(t),p(t))` с учетом противодействия;
- график `P(pA(t),p(t,k))` с учетом противодействия;
- сравнительный график одиночного и коллаборационного режимов;
- таблица `P(p(t,k))` по диапазонам `n=1..8`, `k=1..5`;
- матрица смежности и покрытие.

### 3.3. Диапазоны моделирования

Используются диапазоны из методички:

- `t = 1..17`
- `n = 1..8`
- `k = 1..5`

## 4. Разработка структуры и определение функций программной системы

Система реализована на Ruby on Rails по архитектуре MVC.

### 4.1. Основные модели

`Attack`

- хранит тип атаки и параметры `a`, `b`;
- вычисляет `pA(t)`.

`Experiment`

- хранит параметры запуска `p_single`, `p_ai`, `n`, `k`;
- связан с одной атакой.

`ExperimentResult`

- хранит результаты расчета по каждому моменту времени `t`.

`AdjacencyMatrix`

- хранит матрицу смежности и покрытие в формате JSON.

### 4.2. Сервисные классы

`ProbabilityService`

- реализует базовые вероятностные формулы.

`ExperimentRunner`

- выполняет расчет результатов эксперимента;
- создает записи `ExperimentResult`;
- генерирует матрицу смежности;
- запускает жадный алгоритм покрытия.

`MethodologyReportService`

- подготавливает таблицы и справочные ряды для графиков по методичке.

`MatrixGenerator`

- строит матрицу смежности `15x15`;
- обеспечивает диапазон числа связей `[1;6]`.

`GreedyCover`

- реализует жадный алгоритм минимального покрытия.

## 5. Структура интерфейса

Интерфейс приложения состоит из двух основных разделов:

### 5.1. Раздел атак

Позволяет:

- создавать и редактировать атаки;
- просматривать профиль `pA(t)`;
- анализировать эталонные профили отказов;
- сверять значения с таблицей классификации.

### 5.2. Раздел экспериментов

Позволяет:

- создавать и редактировать эксперименты;
- задавать `p(t)`, `p(ai)`, `n`, `k`;
- просматривать результаты расчета в виде графиков;
- анализировать матрицу смежности;
- получать покрытие.

Для всех графиков и таблиц в интерфейсе даны пояснения, указывающие, по какой формуле построен соответствующий блок.

## 7. Результаты исследования

### 7.1. Сводные таблицы результатов моделирования

В приложении формируются:

- таблица классификации отказов для 6 эталонных профилей;
- таблица параметров индивидуальных вариантов `2`, `5`, `9`;
- таблица `P(p(t,k))` по диапазонам `n`, `k`;
- матрица смежности `15x15`.

### 7.2. Графики зависимостей исследуемых параметров

Реализованы следующие группы графиков:

1. Графики атак:
   - `pA(t)` для конкретной атаки;
   - эталонные профили отказов;
   - средневзвешенное сравнение линейных и экспоненциальных атак.
   - отдельные графики линейных и экспоненциальных профилей для вариантов `2`, `5`, `9`.

2. Графики эксперимента:
   - базовая вероятность одиночного тестирования;
   - базовая вероятность коллаборационного тестирования;
   - вероятность отказа `p(ai) * pA(t)`;
   - вероятность одиночного обнаружения с учетом противодействия;
   - вероятность коллаборационного обнаружения с учетом противодействия;
   - сравнительный график `Single` и `Collab`.

### 7.3. Сравнительный анализ результатов

Анализ полученных зависимостей позволяет сделать следующие выводы:

1. Линейные и экспоненциальные атаки по-разному влияют на форму временных графиков.
2. При увеличении `pA(t)` вероятность обнаружения в условиях противодействия снижается.
3. При большем `p(t)` вероятность обнаружения выше как в одиночном, так и в коллаборационном режиме.
4. Коллаборационная стратегия чувствительна к сочетанию `n` и `k`.
5. При фиксированном `p(t)` базовые графики без противодействия удобнее анализировать по параметрам `k` и `n`, а не по времени `t`.

### 7.4. Выводы

Разработанное приложение позволяет проводить анализ моделей обнаружения уязвимостей в условиях противодействия и соответствует основным требованиям методических указаний. Реализация охватывает как базовые вероятностные формулы, так и сценарии с учетом атакующего воздействия.
